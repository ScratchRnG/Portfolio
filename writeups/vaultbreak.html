Scenario:

In May 2025, a financial services firm detected suspicious activity after an employee opened an urgent document received via email. The workstation exhibited abnormal behavior, including unexpected processes and unusual network connections. Security teams identified evidence of unauthorized system modifications and potential persistence mechanisms.

The investigation focused on reconstructing the attack sequence from the initial phishing interaction through malware execution, process injection, privilege escalation, persistence, and command-and-control activity.

Collected forensic artifacts included browser history, process creation telemetry, PowerShell activity, Sysmon events, registry modifications, WMI persistence records, scheduled task artifacts, and network connection telemetry.

The objective was to determine how the compromise occurred, identify the malicious execution chain, uncover the persistence mechanisms used, and trace the infrastructure supporting command-and-control communications.

Executive Summary

The attack began when the user nevans downloaded the macro-enabled document Financial_Support.docm after interacting with a phishing link. Browser history analysis identified the download at 2025-05-19 15:58:25.371584.

After the document's macro executed, PowerShell retrieved a remote executable named payload.exe and stored it in the user's temporary directory under a randomized filename using the pattern msupdate-####.exe. In this incident, the payload was written and executed as msupdate-2381.exe. The malware also created the configuration file content.inf shortly after execution.

The payload later performed process injection into notepad.exe, helping explain subsequent anomalous Notepad activity. At 2025-05-19 16:09:24 UTC, notepad.exe, associated with WIN-DMZ0\nevans, spawned cmd.exe running as NT AUTHORITY\SYSTEM with PID 10660. This represented a major escalation in execution context and enabled the attacker to establish deeper persistence.

Persistence was established through both Windows Management Instrumentation and Task Scheduler. The WMI mechanism used the compromised account WIN-DMZ0\nevans and was associated with MITRE ATT&CK technique T1546.003. The attacker also created the scheduled task Microsoft\Windows\UpdateOrchestrator\UpdateAssistant and modified its SD registry value under TaskCache. Shortly afterward, a WMI filter-to-consumer binding event linked the malicious persistence components using SID S-1-5-21-403280985-4081385913-4248903659-2063598570.

Attack Timeline

2025-05-19 15:58:25.371584

The user nevans downloaded the malicious macro-enabled document Financial_Support.docm after clicking a link delivered through phishing.

Macro Execution

The malicious document executed a PowerShell command that selected the user's temporary directory, generated a randomized filename using the format msupdate-####.exe, and downloaded a remote payload.exe into that location.

Payload Delivery

The downloaded payload was saved and launched as msupdate-2381.exe. The msupdate naming convention was likely intended to resemble a legitimate Microsoft update component.

Configuration Creation

Shortly after execution, the malware created content.inf, which was used as a configuration file for the malicious payload.

2025-05-19 16:04:58

Sysmon Event ID 8 activity showed msupdate-2381.exe injecting into notepad.exe, indicating process injection and helping explain later execution attributed to the legitimate Windows process.

2025-05-19 16:09:24 UTC

notepad.exe with PID 11028, associated with WIN-DMZ0\nevans, spawned C:\Windows\System32\cmd.exe as NT AUTHORITY\SYSTEM. The command shell ran with PID 10660.

2025-05-19 16:09:32 UTC

svchost.exe running as SYSTEM modified the scheduled-task security descriptor at HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Schedule\TaskCache\Tree\Microsoft\Windows\UpdateOrchestrator\UpdateAssistant\SD.

Scheduled Task Persistence

The attacker established persistence through the task Microsoft\Windows\UpdateOrchestrator\UpdateAssistant, which was configured to execute the malicious encoded PowerShell activity again.

WMI Persistence

The compromised account WIN-DMZ0\nevans was used to create a WMI event filter designed to trigger malicious execution after approximately 10 minutes of system uptime. This behavior maps to MITRE ATT&CK T1546.003.

2025-05-19 16:09:44 UTC

A WMI filter-to-consumer binding event connected the persistence components. The associated SID was S-1-5-21-403280985-4081385913-4248903659-2063598570.

Command and Control

Network telemetry showed the malicious PowerShell activity communicating with external infrastructure used for command and control. Replace 3[.]127[.]36[.]5:8443 below once the final IP address and destination port are confirmed from the network events.

Defensive Takeaways

  • Monitor email and web telemetry for macro-enabled Office documents downloaded from external or newly observed infrastructure.
  • Alert on PowerShell commands that download executables into user-writable paths such as %TEMP%, especially when randomized filenames are used.
  • Hunt for suspicious child-process relationships involving applications such as notepad.exe spawning shells or scripting interpreters.
  • Monitor Sysmon Event ID 8 for remote-thread creation and other process-injection indicators targeting legitimate Windows processes.
  • Alert when user-context processes result in child processes running as NT AUTHORITY\SYSTEM.
  • Review modifications to TaskCache SD values because security descriptor manipulation may be associated with hidden or tampered scheduled tasks.
  • Detect permanent WMI event subscriptions by monitoring filter, consumer, and filter-to-consumer binding creation events.
  • Correlate persistence events across Task Scheduler, WMI, Registry, PowerShell, and process telemetry rather than investigating them independently.
  • Monitor outbound connections from PowerShell and newly created executables to unusual external IP addresses or non-standard destination ports.
